How the agents talk

They leave each other notes. Every one is logged.

Channel 1

A shared workspace

One per run, stored in Meterless memory. Five kinds of note: claim, question, answer, correction, verdict, each with who sent it and who it is for.
Channel 2

Direct hand-offs

Every card goes to the FactChecker; a wrong one goes back to the agent that made it.
Channel 3

A trace anyone can replay

A 10-field log line for every step, including target_agent (who it went to). Readable at GET /api/runs/:id/agent-log.

The rules of the debate

The AI Judge and a plain-code screen both grade. If they disagree: one rebuttal round, then the Judge rules again. A code "reject" always stands. A grade both sides don't agree on is never saved.

Safety gate

ClawbackHunter asks RecallChecker before showing money back on an item. Recalled? The deal is killed.

Counter-question

The Eligibility Lawyer tries to disprove each benefit with one data question: confirmed, dropped, or "Not yet verified".

Send-back

FactChecker returns a wrong amount or date with the exact line, max 2 rounds. Tested; not yet seen in saved logs.

An API other parent apps could use

GET /api/offer-audit?store=Amazon
{ "status": "found", "brands": [ { "store": "Amazon",
  "offersChecked": 3, "offersCaught": 2, "catchRate": 0.667 } ] }
Public, read-only, rate-limited. Fields are copied one by one so no family data can leak. With nothing saved it says "none", never invents rows. Described in a standard OpenAPI file: bundle/docs/openapi/offer-audit.yaml.

The recall question RecallChecker asks today (simplified)
SELECT i.item_text, r.recall_title, r.recall_url
FROM bundle_pg.v_purchase_items i
  -- private · Neon · includes photo rows
JOIN (cpsc_recalls UNION ALL fda_food_recalls) r
  -- live · read from CPSC + openFDA, no copy
  ON r.recalled_product LIKE '%' || i.upc || '%'
 OR r.recalled_product LIKE '%' || i.lot_code || '%' …
WHERE i.family_id = :family
