## Findings, by severity

**F1 — HIGH: capital letters skip the gate.** `bundle/server/middleware/testerCode.ts:87` (`const path = req.path`) and `:118` (`!path.startsWith('/api')`). Express matches routes regardless of upper/lower case, but the gate compares the path exactly, so `/API/run`, `/Api/photo/read`, `/API/runs/:id/events` etc. all work with no code. Proven above (`GET /API/families/maya/gear` -> 200). Fix: `const path = req.path.toLowerCase();` (and the same in `gateHintCookie`, line 136), plus a test `request(a).get('/API/secret')` -> 401. Alternative: build the app with `app.set('case sensitive routing', true)`, but lower-casing in the gate is the smaller change.

**F2 — LOW: one shared wrong-guess counter per connection.** `testerCode.ts:64-78`. Testers on the same Wi-Fi (same public address) share the 10-guess limit, so one person fumbling can lock the room out for 15 minutes. Acceptable for a test; worth one sentence in the guide's Step 4 ("people on the same Wi-Fi share this limit").

**F3 — LOW: the "made-up details" notice disappears after the gate.** `client/src/components/gate/TesterGate.tsx:72-78` is the only place it shows. Testers type family details later, in onboarding, where the notice is gone; with no code set it never shows at all. Meets the done condition as written; consider a small repeat line on the onboarding screens if wanted.

**F4 — LOW: no re-gate mid-session.** `TesterGate.tsx:21-33` checks once on load. If the code is changed while a phone has the app open, every request returns 401 and the app shows its generic error screens, not the gate, until the page is reloaded. Fix (optional): on a 401 with `code: 'tester_code_required'` in the shared fetch helper, reload the page.

**F5 — LOW: wrong header gives the "code needed" message, not "wrong code".** `testerCode.ts:125-128`. Only affects scripts; cosmetic.

**F6 — LOW: hint cookie set on every file download.** `testerCode.ts:134-140` sets `bundle_gate=on` on every non-/api response, including every JS/CSS/image. Harmless, slightly noisy; could limit to responses for HTML pages.

**F7 — INFO: localhost always allowed by CORS in production.** `server/index.ts:44-50`. Fine here: the cookie is SameSite=Lax, so other sites' pages can't send it, and CORS is not the lock. Worth knowing, not worth changing.

**F8 — INFO: one proxy hop trusted.** `TRUST_PROXY=1` (render.yaml) uses the last address Render adds. Confirmed secure cookies and per-visitor limits work with that setting locally; whether Render puts exactly one proxy in front was not checked live (check after deploy: two phones on different networks should not share a lockout).

Good things: code compared in constant time (both sides hashed then `timingSafeEqual`), cookie holds a fingerprint (changing the code logs everyone out), HttpOnly + SameSite=Lax + Secure behind HTTPS, the code is never logged, the gate is mounted before every route (all `/api` routes are registered later in `registerRoutes`), tests cover lockout and recovery.
