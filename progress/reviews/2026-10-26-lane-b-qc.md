## Loophole review (c)
- **Is the AI Judge toothless?** Partly. An AI "reject" that cites no learned rule can now give at most a catch. If the AI's quote isn't an exact copy of the fine print, the result is a **plain approve** (`combineVerdict`, `finePrintRules.ts:169`): `combineVerdict(approve, {reject, quote:''})` returns `approve`. Combined with H1, a new kind of subscription trap that the code rules miss gets through, even when the AI correctly says reject. A judge who pastes "Free first box, then $24.99/month" into the parent-paste flow would see it approved. The README still says the Court "**Yes: rejects offers**" (`README.md:47`). That is true only through the code rules and learned rules.
- **Planted trap and prompt injection:** still blocked. Cuddle & Co is rejected by the code rules alone (auto_renew + card_required; row 19). The injection text gives `prompt_injection`, which rejects. The trap card carries no example.com link (`isDemoUrl`).
- **Learning loop:** works. Offline run 1 approves "Amazon Subscribe & Save diaper discount". Parent reports lead to rule mem-28 ("Reject offers whose savings depend on keeping a subscription active"). Run 2 blocks it, cites mem-28, and wrongly blocks nothing else. A newly learned rule also overrides a saved grade (`finePrintCourt.ts`, `saved_grade_outdated`). But: (1) the obvious trap is now blocked in run 1, so `obviousTrap.run2Blocked` is false. (2) `README.md:185` still says the offline court "does not catch a free trial that auto-renews… until a parent-reported rule teaches it". That is now wrong (M2). (3) The demo blocks a real, legitimate Amazon offer through a learned rule, which conflicts with rule 1. That is fine as a deliberate design choice, but the presenter should say it out loud.

## Findings by severity

**HIGH**
- **H1. A trial that turns into a paid plan isn't seen as renewing unless the word "renew" or "billed" appears.** `finePrintRules.ts:76-77` (RENEWAL / AUTO_RENEW). These slip through:
  - "then $14.99 per month";
  - "continues at $19.99/month unless you cancel";
  - "then $24.99 per month. Cancel anytime."

  Fix: add these alternatives to AUTO_RENEW:
  - `\bthen\s+\$\s?[\d.,]+\s*(?:\/|per|a|each|every)\s*(?:week|month|year|mo)\b`
  - `\b(?:continues?|converts?)\s+(?:at|to)\b[^.;]{0,30}\$`
  - `\buntil\s+you\s+cancel\b`
  - `\bunless\s+(?:you\s+)?cancel`

  Add matching groups to RENEWAL. Then add regression tests for all three sentences.
- **H2. "Costs more than it's worth" is missed with common value wording.** `finePrintRules.ts:71` FACE_VALUE handles "($100 value)" but not:
  - "(a $100 value)" (Walmart's own page uses "(a $99 value)");
  - "worth $99";
  - "$100 value" without brackets.

  Fix: `\(\s*(?:an?\s+)?${AMT}\s+value\)|\b(?:valued\s+at|worth)\s+${AMT}|${AMT}\s+value\b|${AMT}\s+(?:back|off)\b`. Test with "Free kit (a $100 value). Pay $120 for shipping." and expect a reject.

**MEDIUM**
- **M1. An AI reject with no exact quote gives a plain approve.** `finePrintRules.ts:169`. Fix: when the AI says reject or catch and the quote doesn't match, keep the code verdict but log `ai_flag_unquoted` in the trace, and show it as "AI raised a concern we couldn't confirm". Optionally, when the AI says reject with an exact quote, run `checkFinePrint(quote)` with the H1 patterns, so a confirmed subscription trap blocks.
- **M2. Stale README.** `README.md:185` describes the old offline screen: it says Prime and "may apply" fees reject, and that the auto-renew trap is not caught until learned. Both are now wrong. `README.md:47` should say "blocks via code rules and learned rules; AI can add catches". Also update the learning-demo text: the obvious trap is now caught in run 1, and the subtle Subscribe & Save one is the learning example.
- **M3. Two new false catches:**
  - `cardRequired` (`:125`) matches "No credit card required". Fix: use `firstUnnegated` for cardRequired, as is done for MEMBERSHIP_NEEDED.
  - `FEE_MAY_APPLY` (`:34`) matches "Free shipping will apply". Fix: add the lookbehind `(?<!free\s)` before `shipping`.
  - Two phrases are missed: "Standard shipping rates apply" and "You pay shipping". Fix: add `rates?` to the fee nouns, plus `\byou\s+pay\s+(?:for\s+)?shipping\b`.
- **M4. Age windows don't match the live pages,** so parents can be shown offers they can't get:
  - Babylist box (seed/Neon 1317): age window is -280..365. The page says the "arrival date must be between four weeks ago and up to nine months away". Use -270..28.
  - Amazon completion discount (1324): maxAgeDays is 120, but the page says it "expires 90 days after the Arrival Date". Use 90.
  - Target Welcome Kit (1320): `valueCents` is null although the fine print says "valued at $100", so the card shows no headline value. Set it to 10000.

**LOW**
- **L1. The AI gives different answers on different runs.** Enfamil live offer `live-07beb87cdcbe` was graded catch (row 31, ai_found_catch) and later approve (row 38). Saved grades hide this in the demo, but a re-run can flip the card.
- **L2.** `offerScreen.offlineProblem` (`offerScreen.ts:15-18`) still uses the old stricter rule. It filters stand-in offers in `fallback.ts:47`. Now that MEMBERSHIP_NEEDED and FEE_MAY_APPLY match more wording, more stand-ins are dropped (for example the Amazon box and the Target kit). That is intended ("stand-ins never need a membership"), but the comment at `finePrintRules.ts:259` says it is the "same rule", and it no longer is. Fix the comment.
- **L3.** On long web pages, an end date counts only if its own sentence repeats a title word (`finePrintRules.ts:291`). "Get a free photo book. Offer expires July 31, 2026." is not caught as expired, because the date's sentence doesn't name the offer. This is conservative (it never wrongly blocks), but it under-detects. Consider also checking the sentence before the date.
- **L4.** `MEMBERSHIP_NEEDED` misses "Must be a Walmart+ member" (`\w+` can't match the "+") and "Available to members only". Fix: `[\w+]+` and `\bmembers\s+only\b`.
- **L5. Untested branches:**
  - `saved_grade_outdated` (a learned rule overriding a saved grade);
  - `isDemoUrl`;
  - `modelNameOf` falling back to the configured model;
  - `accuracyRun.ts` (73 lines, not in package.json and no tests: either add an npm script or mark it as a one-off).
- **L6.** `links:check` doesn't scan links written directly in `client/src`. Fix: add a regex sweep of `client/src/**/*.ts(x)` for `https://` literals, skipping `__tests__`/`__acceptance__` and `*.test` hosts.
- **L7.** The catch type `shipping_fee` is also used for "processing fee" and "handling fee" (it is only a label).

## Bottom line
Conditions 2–6 pass. Condition 1 is right in its logic but has two gaps in what the code recognizes (H1 and H2). Together with M1, these let a real "free trial, then $X/month" offer through, even when the AI correctly says reject. H1, H2, M2 and M3 are each under an hour of work, and each comes with a ready-made test sentence above.
