**Words used a lot here**
- **Fallback:** a pre-written or rule-based answer the app uses when the AI doesn't respond.
- **Trace:** the step-by-step log of one run, one line per agent step.
- **Repo:** the GitHub folder judges download the code from.
- **Gate:** a pass/fail rule. Fail it and the score doesn't matter.
- **Nightshift:** Meterless's app that turns your Mac into a private AI server for other apps.
- **H-MEM:** Meterless's memory engine (the "engine" Bundle uses).

## 6. Red flags a judge would catch

1. **The required main AI is missing.** No Nightshift anywhere in the code, README, deck or metadata. Under today's rule, that is a gate failure, not just lost points.
2. **Every saved AI result is a fallback.** In `logs/sample/maya.jsonl`, 26 of the steps are fallbacks. All 10 of the Deal Hunter and Lawyer "argue" lines read "model unavailable", every Judge ruling is `rule_by_screen` (the keyword screen), and the Coach's rule is one of two pre-written sentences. The README (§8) and deck (slides 7 and 9) admit this honestly, which helps. But a judge will still score what the AI *did*: nothing.
3. **In the one real-AI run (today, on your Mac, interrupted), the Court contradicted itself.** I started `npm run eval`, expecting it to run offline. It picked up your NVIDIA key and called the real model (Red flag 4). The Lawyer correctly said the "free" diaper box "turns a promotional offer into a trap... if you don't cancel within 30 days". But the Judge fell back on 4 of 5 offers, and the keyword screen **approved the trap** ("Offline screen: no flagged terms found") (`logs/run-maya-b7873fb4-….jsonl`, git-ignored). Likely cause, not yet confirmed: the reasoning model takes longer than the 20-second timeout (`llm.ts:38`), or adds text around its JSON answer (JSON is the strict machine-readable format the code expects). Explanations also fell back. Fix with action 4 before any real-AI recording.
4. **`npm run eval` is not offline on your Mac.** The eval script ignores `SAMPLE_MODE`. With your private keys present, it calls the real AI, and goes to live Zetaris for any query that has no saved answer (`scripts/eval.ts:108-117`). Harmless for judges (they have no keys). But if it's run before a recording, the scoreboard could quietly change. Say "with keys, eval is live" in the README, or make it obey `SAMPLE_MODE`.
5. **The AI Judge has the final say on offers.** The code-level fee and membership checks only run when the AI is down (`finePrintCourt.ts:57-63, 103-115`). Fine print is pasted into the prompt unmarked (`finePrintCourt.ts:75, 94-100`). So a cleverly worded offer could talk the Judge into approving it (this is called "prompt injection"), and no test checks for it.
6. **"Take either one away and Bundle stops working"** (deck slide 10). True for Zetaris. For Meterless, removing H-MEM only stops the learning demo; everything else still runs. Soften it to "the Court never learns".
7. **"Each agent sees only its own governed view / the Judge never sees family income"** (deck slides 6 and 10). True in the code (`scripts/zetaris/register.ts:31-49`), but not locked by permissions: Zetaris connects as the database owner (`plans/architecture.md` §7f). Add "enforced by views; permission grants are the production step."
8. **Numbers that don't match:** deck slide 9 shows rule confidence **0.8** (the eval uses 3 parent reports). The video script says **70%** (the live demo uses 2 reports; `coach.ts:25`). Both are right for their own run, but a judge sees a contradiction. Use one in both, or explain the difference.
9. **Zetaris's cross-source join happens in one agent only.** Benefits, poverty limits and ZIP lookups all live in Neon, and the poverty table is seeded (copied in once), not a live feed. Don't imply that four live sources are joined. The README is careful here; keep the deck that careful.
10. **Recall alarm wording.** An AI "yes" on a loose name match still produces a card titled "Recall alert" (`recall.ts:117`). Finished FDA recalls aren't filtered. CPSC 10490 and 10453 are known near-misses. Scaring a parent with a wrong recall is the worst failure for this product (action 7).
11. **Work benefits assumed for everyone.** Typed-in families are treated as having a Dependent Care FSA (a work benefit for paying daycare with pre-tax money) (`bundleRoutes.ts:97`). That can inflate the money a real parent sees.
12. **The value claim isn't in the repo.** The ~$9,210 figure sits in `research/research-boston-baby-benefits.html` outside `bundle/` (README:18). Judges discount value claims they can't trace. Put a short, sourced table in the repo or deck.
13. **Results and traces are public and temporary.** Anyone with a run link can read its trace and debate. Results vanish on restart (`bundleRoutes.ts:19, 111`).
14. **Wording-rule slips in planning docs.** `plans/onboarding-spec.md` says Meterless gives Bundle "memory... and safety checks", which breaks your own rule ("Meterless = memory, not fine-print reading"). Make sure it doesn't leak into the deck or video.
15. **Placeholders and formalities.** `metadata.json` has 4 `REPLACE-ME` links. The video plan runs 3:55 against a 4:00 cap. Keep proof that Cursor is optional, since the official overview still lists it as required.

**What a judge will credit (keep these exactly as they are):** the honest "offline" labels everywhere, money calculated in code (never by the AI), the Fact-Checker's send-back loop with saved traces, the learning loop that's proven by a test (`server/__tests__/sampleMode.test.ts`), and the "no keys needed" sample mode that replays real Zetaris answers instead of making them up.
