# Lane A QC: screens and wording (Oct 26, 2026)

Independent check by a reviewer who did not build Lane A. Nothing was edited in the app. Nothing was committed.

**Plain-English key**
- **Practice mode:** the app runs on saved sample data, with no paid AI or outside services.
- **Headless browser:** a real Chrome with no window, driven by a small script so it can take screenshots.
- **Owner view:** what judges and Lyndsay see after typing the reviewer code. Parents never see it.
- **mailto: link:** a web link that opens the computer's email program with a new message already filled in.

## Findings (tightness review)

### Medium
- **M1. The tax-credit share tells the parent to "tap Copy", but there is no Copy button there.**
  - **Where:** `client/src/pages/tabs/TaxBooster.tsx:81-86` (`share()`) and `:107-108`.
  - **What happens:** the button "Send these to your partner or tax preparer" now uses `sendToSelf`. On a computer it shows `OPENING_EMAIL`, "…If nothing opens, tap Copy and paste it into an email." That card has no Copy button. If sending fails, `EMAIL_FAILED` sends the parent to a button that is not there either. Only the HR page has Copy.
  - **Fix:** either add a Copy button to the booster card (copy the same `text` with `navigator.clipboard.writeText`, as HrQuestions does), or let `sendToSelf` take the fallback wording, for example "If nothing opens, copy the numbers above into an email."

### Low
- **L1. Parents can still see or hear "memory" in three places.**
  - **Where:**
    - `client/src/pages/tabs/FamilyChipMenu.tsx:59`: the menu item "Your plan and memory ›".
    - `AccountTab.tsx:311`: the screen-reader label "Memory about your family".
    - `AccountTab.tsx:367`: "…the memory entries about your family…" in the Forget-everything confirm step.
  - **Fix:** use "Your plan and profile", "What we know about your family" and "…what we saved about your family…".
- **L2. A phone briefly says "Opening your email…" when it is really opening the Share sheet.**
  - **Where:** `HrQuestions.tsx:30` and `TaxBooster.tsx:84`. Both set `'Opening your email…'` before `sendToSelf` decides between the Share sheet and email.
  - **Fix:** say a neutral "Opening…", or let `sendToSelf` report which path it took.
- **L3. Desktop wording says "tap".** `OPENING_EMAIL` and `EMAIL_FAILED` (`lib/sendToSelf.ts:12-13`) say "tap Copy" even on a computer. **Fix:** say "use Copy".
- **L4. Tests that lost a check, with nothing added in its place:**
  - **`LaneE.test.tsx` ("Save your plan") and `VersionB.test.tsx` ("light extras"):** they no longer check that the name is saved in the browser (`localStorage bundle:plan:<id>`). They also no longer check that the name is still there after the screen is drawn again. Add `expect(localStorage.getItem('bundle:plan:guest-ab12cd34')).toMatch(/Our baby plan/)` after "Save name", then draw the page again and check `family-name`.
  - **`Feed.test.tsx`:** the check that owner-only fields never reach the page (`not.toMatch(/owner-trace-id|real-?time/)`) now runs only in the owner view. LaneA item 8 does not repeat it for a parent. Add the same line to the LaneA item 8 test.
  - **`s6-account.test.tsx`:** it dropped "raw `mem-` ids appear after tapping Technical details". The LaneA owner test counts the 2 buttons but never taps one. Add a tap there and check `mem-\d+` appears.
  - **The `Checking recalls…` assertion:** it was moved into the LaneA item 8 test, not lost. OK.
  - **The other edited tests** (LaneB, LaneD, s3, s5, InsuranceTab): each was updated to the new wording or placement, with an equal or stronger check. Not weakened.
- **L5. The Trump card's "Source" link may sit next to "How we checked" in the owner view.**
  - **Where:** `shared.tsx:54-55`.
  - **What happens:** `sourceHref` is only set when `showsHowWeChecked` is false, so the owner view is fine today. But `FeedCardView` shows Source only when `!detailHref`. A future caller passing both props gets one silently dropped.
  - **Fix:** a one-line comment on the `sourceHref` prop is enough.
- **L6. The Home bucket depends on one hard-coded card id.**
  - **Where:** `shared/cardMeta.ts:54`.
  - **What happens:** `isBabySavings` checks the single id `benefit-trump_account`. The builder already noted that the server still tags this card `tax_time` (`server/__tests__/laneB.test.ts:56`).
  - **Fix:** fine for the hackathon; add a `baby_savings` category on the server later.

### Clean
- **No leftover code:** `SavePlanCard`, `PlanInfo` and the old test ids (`save-card`, `save-confirm`, `save-name-input`) have no live references. The only remaining mentions are "is absent" checks in tests. The unused imports in `Extras.tsx` were removed. `TaxExtras` lost its `filing` prop, and its caller was updated.
- **`sendToSelf` handles failures properly:** closing the Share sheet (`AbortError`) is treated as not an error. Other Share errors fall back to email. An email failure shows a visible message. A `canShare` error is caught.
- **Accessibility:** new buttons have visible text, and the plan-name field has a `<label>`. Tap targets are at least 44 px. The new green text `#17643F` on the cream background has strong contrast (about 7:1). "Source" uses the same grey as the existing links.
- **The 529 card stays in step with Taxes:** it reads the same saved answer (`useFiling`) as the Taxes booster. A live test confirmed it shows "$1,000 single / $2,000 together" before an answer is given.
- **Plain English:** the new parent wording is plain throughout. Two small ones: "firm them up" is fine. "Quick check only. Read the terms before you sign up." is clear.
