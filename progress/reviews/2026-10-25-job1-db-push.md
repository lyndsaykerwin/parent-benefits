# Job 1: applying database change `0002_v2_foundation` to Neon (Oct 25)

**Result: partly applied, then stopped. No data lost. Nothing was dropped. The rest still needs to be applied, by a different method.**

## What the change is meant to do (`bundle/migrations/0002_v2_foundation.sql`)
It only adds things:
- New table `claims` (id, family_id, card_id, status, created_at, plus a rule that each family/card pair appears once).
- New table `item_photos` (id, family_id, kind, thumbnail, receipt_image, created_at).
- New columns on `families`: household, parent1_work, parent2_work, insurance, saved_at.
- New column on `offer_checks`: source (filled with 'court' for existing rows).
- New column on `purchase_items`: photo_id.

Before pushing I compared the live database with the code's table list (`shared/schema.ts`): every column that exists in Neon also exists in the code, so no table or column would be removed.

## What happened when `npm run db:push` ran
`db:push` (drizzle-kit 0.31.5) does not run the migration file. It compares the code with the live database and writes its own list of changes. Its list contained more than the migration:
1. It created `claims` and `item_photos`. **Done (both empty).**
2. It then tried to remove dozens of "must be filled in" rules (`..._not_null` constraints) on almost every table, and to remove `spike0_amazon_orders_id_seq` (the counter of a table that is not Bundle's and that the config tries to protect).
3. The first of those removals failed ("column id is in a primary key"), so the push stopped there.

Root cause: Neon runs PostgreSQL 18.6. Version 18 stores "must be filled in" rules in a place this drizzle-kit version does not understand, so drizzle-kit wrongly thinks they are extra and should be removed. This is a tool bug, not a problem with the change itself.

## Checked after the failure
- Row counts are the same as before in every table (for example families 6, offer_checks 7, purchase_items 11, spike0_amazon_orders 5, zip_states 929).
- "Must be filled in" rules are still in place (checked tax_parameters, amazon_orders, users, spike0_amazon_orders).
- The spike0 counter still exists and is still used.
- Tables now in Neon: amazon_orders, benefit_rules, case_law_proposals, **claims**, families, feedback, fsa_eligible_categories, **item_photos**, offer_checks, offers, price_observations, purchase_items, run_results, spike0_amazon_orders, state_programs, store_policies, tax_parameters, transactions, users, zip_states.
- **Still missing:** the 5 new `families` columns, `offer_checks.source`, `purchase_items.photo_id`. Real mode (not practice mode) will fail on those until they are added.

## Database tests
These tests run only against a local throwaway database (`TEST_DATABASE_URL`, created by `npm run db:test`) and refuse anything that is not local, by design. DATABASE_URL does not turn them on, and they never touch Neon. None were run here: 0 passed, 0 failed (not applicable).

## Recommended next step (needs the owner's go-ahead)
Do not run `db:push` again on this database with this drizzle-kit version: it would try the same removals.
Instead, run the remaining 7 "add column" lines from `0002_v2_foundation.sql` directly, inside one all-or-nothing transaction. They only add columns. Then list the columns to confirm.
