# Job 4: real AI answers for the sample photos (Oct 25, 2026)

Handoff item: `progress/handoffs/2026-10-25-v2-cloud-handoff.md`, "Final state", item 4. Nothing committed.

## What I found first
- `data/sample/photos/` had **no photos at all**, so `npm run record-vision` had nothing to record. I drew two
  made-up pictures with a small script (no real people, addresses or card numbers; both say "sample" on them):
  - `bundle/data/sample/photos/item-graco-sample-label.png`: a car-seat label, Graco, model SAMPLE-1042, lot SMP-0315, UPC 0 12345 67890 5.
  - `bundle/data/sample/photos/receipt-made-up-baby-mart.png`: "Made-up Baby Mart", Oct 20 2026, thermometer $12.99, nasal aspirator $8.49, diapers 84ct $24.99, total $46.47.
- The recorder does **not** replace `sample-photo-answers.json`. It saves real answers to `data/sample/vision-cache/`,
  one per picture "fingerprint" (a code computed from the picture's exact bytes). The made-up file stays as the
  fallback for any other photo, and the screen still labels that case as made-up. Correct, so it stays.
- **Bug found and worked around:** before upload, the browser redraws every photo as a fresh JPEG (to strip location
  data). So the uploaded bytes never match the file on disk, the fingerprint misses, and practice mode fell back to the
  made-up answer (seen in the server log: "fallback: no saved vision answer"). Fix without code changes: I made the
  exact copies Chrome uploads (`*.browser.jpg`, same canvas steps as `client/src/lib/photoPrep.ts`, checked twice: same bytes)
  and recorded those too. Safari may encode slightly differently and would get the labelled made-up answer.
